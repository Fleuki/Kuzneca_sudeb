# Кузнец Судеб

Роглайт про кузнеца, который сам испытывает свою работу. Забег состоит из трёх фаз:
**добыча → ковка → бой с боссом**. Главное отличие от прочих роглайтов в том, что
игрок знает, какой босс его ждёт, **до того как идёт в шахту**, — поэтому сбор
ресурсов превращается из грайнда в планирование, а бой становится проверкой плана.

Реализация MVP по дизайн-документу v1.0. TypeScript + Vite + PixiJS 8, без ассетов:
всё рисуется примитивами.

---

## Запуск

```bash
npm install
npm run dev        # разработка, http://localhost:5173
npm run build      # продакшен-сборка в dist/ (относительные пути — годится для itch.io)
npm run preview    # посмотреть собранное
```

Инструменты:

```bash
npm run determinism            # проверка: один сид → один результат
npm run balance                # прогон боёв ботами, таблица винрейтов
npm run balance -- --runs 100                  # больше прогонов
npm run balance -- --boss abyss                # только один босс
npm run balance -- --tier 3                    # оружие из узлов третьего уровня дерева
npm run balance -- --inlay basalt              # со вставкой в рецепте
npm run mine-check             # проходимость шахты: до всей ли руды можно допрыгнуть
npm run mine-check -- --verbose               # где именно руда недостижима
npm run deadlock-check         # проверка, что забег нельзя загнать в тупик
npm run input-check            # отзывчивость: тап берёт ступеньку, зажатая кнопка бьёт повторно
npm run feel-check             # ощущение удара: заморозка кадра, отскок, отбрасывание
npm run typecheck
```

`mine-check`, `deadlock-check`, `input-check` и `feel-check` гоняются в CI на каждый пуш. Оба появились после
первого плейтеста и закрывают ровно те ошибки, которые он вскрыл (см. ниже).

## Где играть

Сборка публикуется на GitHub Pages автоматически: workflow `.github/workflows/deploy.yml`

Чтобы это работало, в настройках репозитория **Pages → Source** должно стоять
**GitHub Actions**, а не «Deploy from a branch».

### С телефона

Игра управляется и с сенсорного экрана — отдельной сборки для этого не нужно.

- **В меню, на выборе босса и биома, в кузнице** — тап прямо по карточке, клетке
  рюкзака или строке. Мышью на десктопе это тоже работает.
- **На верстаке** — тап по клетке сразу кладёт предмет в слот, отдельные кнопки —
  «Соединить» и «Очистить». Вкладки «Верстак» и «Наковальня» переключаются тапом.
- **В шахте и в бою** — экранные кнопки: движение слева, действия справа.
  В бою слева добавляется «▼» — прицел вниз: с ним удар в воздухе становится
  ударом с отскоком.
  Палец можно вести с одной кнопки на другую, не отрывая от экрана.
  Кнопка «Наверх» появляется, только когда дошёл до подъёмника.
- **На наковальне** — тап по краям строки листает значение, тап по середине
  переносит фокус.
- **В мини-игре ковки** — тап в любое место экрана.
- **Если материала не хватило** — кнопки «В шахту» и, при полном рюкзаке, «Выбросить».

Кнопки — 88 px с зазором в 24 px и запасом попадания ещё в 20 px по кругу; при
пересечении запасов срабатывает ближайшая по центру. Зажатая кнопка удара бьёт
повторно, а тап по прыжку удерживается до вершины — иначе гашение высоты срезало
бы прыжок ниже ступеньки в шахте.

Кнопки появляются только там, где есть касания, и прячутся на десктопе. Подсказки
внизу экрана меняют формулировку под текущий способ управления.

Игра рассчитана на 16:9, поэтому в портретной ориентации показывается просьба
повернуть телефон.

## Архитектура

Требования §11 дизайн-документа выполнены буквально, потому что именно они
окупаются балансировкой ботами.

```
src/
  core/          чистые данные: типы, константы баланса, ГПСЧ, команды
  sim/           симуляция. НИ ОДНОГО импорта из PixiJS или DOM
    mine/        генерация шахты из ручных сегментов и её шаг
    forge/       вывод характеристик оружия и мини-игра
    combat/      игрок, боссы, опасности, расчёт урона
    game.ts      корень: dispatch(команда) и tick()
  render/        PixiJS. Только читает состояние и рисует
  input/         клавиатура и сенсорный экран → команды
  persist/       сохранение между фазами
tools/           бот, балансировщик, проверка детерминизма (headless, без браузера)
```

**Симуляция отделена от рендера.** `src/sim` не знает про PixiJS: балансировщик
в `tools/` гоняет ту же самую боевую систему в Node без единой строчки рендера.

**Фиксированный шаг 60 Гц** с накопителем в `main.ts`, интерполяция при отрисовке
(каждая сущность хранит `px`/`py` — позицию на прошлом тике).

**Детерминированное состояние.** Всё состояние — простые JSON-данные, включая
состояние ГПСЧ. `npm run determinism` прогоняет одинаковые сценарии дважды и
сравнивает результат посимвольно. Рендер использует собственный источник времени
для косметики (тряска, мерцание) и никогда не трогает ГПСЧ симуляции.

**Мутации только через команды.** UI не меняет состояние напрямую — даже навигация
по меню идёт через `MENU_MOVE` / `MENU_CONFIRM`, чтобы поток команд можно было
записать в реплей. Сенсорный ввод идёт тем же путём: тап превращается в те же
команды, что и клавиша, поэтому симуляция про существование телефона не знает.
Способ управления сознательно не хранится в состоянии — иначе один и тот же сид
давал бы разные результаты на телефоне и на десктопе.

**Сохранение между фазами** (§2): состояние целиком пишется в `localStorage` на
каждом переходе фазы, раз в 5 секунд и при закрытии вкладки. Можно закрыть браузер
после добычи и вернуться к ковке позже. Хранилище спрятано за интерфейсом `Storage`
в `persist/save.ts` — под Яндекс Игры туда подставляется `player.setData` из SDK.

### Дерево крафта вместо рецепта «12 + 6»

Исходный рецепт (12 единиц основного материала + 6 вторичного) был выбором из
четырёх строк, и вся фаза добычи сводилась к «набей двенадцать штук одного».
Вместо него — дерево предметов (`src/core/items.ts`) с одним правилом:
**два предмета дают один**.

```
руда ×2            →  слиток                (4 узла)
слиток + слиток    →  сплав                 (4 чистых + 6 гибридов)
сплав + сплав      →  сплав 3-го уровня     (6 узлов)
сплав3 + сплав3    →  вершина дерева        (2 узла)
```

Из одинаковых получается «чистая» ветка (две железные пластины → сталь), из разных —
гибрид, наследующий свойства обоих (обсидиан + кристалл → пустотное стекло, которое
наполовину проходит и броню, и щит). Всего 26 узлов и 22 рецепта.

**Цена читается по дереву.** Каждый уровень удваивает расход сырья: слиток — 2 руды,
сплав — 4, третий уровень — 8, четвёртый — 16. Оружие съедает **две** единицы основы,
то есть стоит вдвое дороже неё. Рюкзак на 20 ровно дотягивает до оружия третьего
уровня без вставки — это и есть главный размен фазы добычи, и он выражен числами,
а не текстом на экране.

**Рецепты открываются, а не читаются.** Неизвестная пара показывается как «???»,
и первое соединение отмечается вспышкой и строкой «Открыто: …». Открытые узлы
живут в мета-прогрессии (`meta.known`) и переживают забеги.

**Крафт уплотняет рюкзак.** Единица любого уровня занимает один слот, поэтому две
руды, ставшие слитком, освобождают место. Из-за этого исчез один из старых тупиков:
полный рюкзак разнородной руды теперь не приговор, а материал для верстака.

Кузница поэтому делится на две вкладки: **верстак** (сетка рюкзака, два слота и
кнопка «Соединить») и **наковальня** (форма, основа, вставка и карточка того, что
получится). Сырьё на наковальню не пускают вовсе — сначала горн.

### Добыча: жилы разного размера и слабое место

Раньше вся руда была одинаковой: два удара, две единицы. Теперь у добычи есть
собственная механика, а не только платформинг между ловушками.

- **Размер жилы.** Обычная — 2 удара, крупная — 5 ударов и вдвое больше руды,
  самородок — 3 удара и сразу готовый **слиток** вместо сырья. Крупная жила не
  «больше руды бесплатно»: стоять на месте вчетверо дольше в шахте с ловушками дорого.
- **Слабое место.** После удара порода отзывается: через 0.2 с на жиле загорается
  точка и держится 0.34 с. Удар в этот момент раскалывает жилу целиком и даёт
  +1 единицу — крупная жила в пять ударов ломается за два. Окно чуть шире
  перезарядки кирки (0.32 с), так что попадание зависит от ритма, а не от везения.

Это тот же навык, что и в мини-игре ковки, только в фазе добычи: держать кнопку
теперь строго хуже, чем бить вовремя.

### Решения по открытым вопросам (§12)

1. **Ломается ли оружие при поражении** — пока ломается, как записано в §8.
   Флаг `KEEP_WEAPON_ON_DEFEAT` в `core/constants.ts` вынесен на видное место,
   чтобы проверить оба варианта на плейтесте.
2. **Сколько боссов на экране выбора** — от одного до трёх: боссы открываются
   по мере побед. Первый забег даёт одного, к финалу выбор становится настоящим.
3. **Режим «испытание»** — не делался: это контент сверх MVP.

### Что вскрыл первый плейтест

Три ошибки, найденные живой игрой, и то, чем они закрыты.

1. **До половины руды нельзя было допрыгнуть.** Комнаты я нарисовал, ни разу не
   сверив с высотой прыжка: платформы стояли ярусами через 3–7 рядов, а прыжок
   брал 76 px, то есть чуть больше трёх тайлов. Проверка показала, что недостижимо
   82% жил, а в худшей шахте доступна ровно одна. Комнаты перерисованы ярусами
   13/10/7/4 под высоту прыжка, а ряды 14–15 оставлены сквозным коридором:
   плита прямо над головой идущего по полу перекрывала проход через комнату.
   Появился `npm run mine-check` — он строит граф мест, где можно стоять, и не
   даёт правкам комнат снова разойтись с физикой.

2. **На платформу арены нельзя было запрыгнуть.** Она висела в 132 px над полом
   при прыжке в 76 — за всю игру на неё не вставал никто. Прыжок поднят до 97 px,
   платформа опущена до 82 px над полом. Баланс после этого перепроверен: материалы-
   ответы по-прежнему в лидерах у всех троих боссов.

3. **Кузница была тупиком.** Игрок вышел из шахты с шестью единицами руды: ковать
   не из чего, вернуться нельзя, выйти можно было только перезагрузкой страницы.
   Добавлены «спуститься ещё раз» (возвращает на выбор биома, рюкзак сохраняется,
   здоровье — нет: цена лишнего захода та же, что и первого) и «выбросить материал»
   для второго тупика, который нашёлся по дороге, — полного рюкзака, в котором
   ни один материал не дотягивает до рецепта (8/6/4/2 при вместимости 20).
   `npm run deadlock-check` проверяет оба случая.

   С деревом крафта второй тупик исчез сам: разнородная руда теперь соединяется
   в слитки и уплотняет рюкзак. Проверка переписана под новые тупики — горсть
   сырья, которой не хватает даже на переплавку, и полный рюкзак несоединяемых
   остатков.

### Что вскрыл второй плейтест

Жалоба была «попадать по кнопкам трудновато, и не всегда как будто работают».
Промахи оказались только частью правды — нашлись две настоящие ошибки.

1. **Удар читался по фронту нажатия.** Зажатая кнопка кирки била ровно один раз
   и дальше молчала: чтобы ударить снова, нужно было оторвать палец. Теперь и
   кирка, и оружие повторяют удар, пока кнопка зажата.
2. **Короткий тап по прыжку давал подскок в 59 px при ступеньке в 72 px.** Палец
   отрывался задолго до вершины, и включалось гашение высоты — забраться было
   нельзя. Экранная кнопка прыжка теперь удерживается до вершины
   (`PLAYER.touchJumpHold`), и тап даёт 92 px. Управление высотой при этом
   сохранилось: осознанно короткое нажатие с клавиатуры по-прежнему даёт низкий
   прыжок.

Заодно кнопки увеличены с 72 до 88 px, зазор между ними поднят с 12 до 24 px,
запас попадания — с 6 до 20 px, и при пересечении запасов выбирается ближайшая
кнопка, а не первая в списке. Точка входа в шахту и подъёмник сдвинуты от краёв
уровня: камера упирается в границу, и персонаж оказывался прямо под кнопками.

Всё это закрыто `npm run input-check`.

### Отступление от документа, которое стоит знать

**В шахте нельзя умереть насмерть**: здоровье не опускается ниже 1 (`MIN_MINE_HP`
в `sim/mine/step.ts`). Документ говорит только, что урон переносится в бой, и молчит
про смерть в шахте. Смерть до боя ломала бы структуру забега — игрок терял бы забег,
ни разу не проверив свою подготовку, то есть ровно ту вещь, ради которой игра и
существует. Ловушки при этом остаются болезненными, потому что урон идёт в бой,
а бросить безнадёжный забег можно в любой момент по `Esc`.

## Ощущение боя

Отдельная работа, которая не меняет ни одного числа баланса, но меняет всё
остальное: до неё попадание по боссу читалось только по укоротившейся полоске.

**Заморозка кадра (hitstop).** В момент попадания симуляция замирает целиком:
и игрок, и босс, и снаряды, и все перезарядки. 30–120 мс в зависимости от того,
насколько тяжёлым был удар. Заморозка общая, а не только для бьющего: останови
одного — второй поедет сквозь застывшую картинку, и вместо удара выйдет рассинхрон.

Живёт она в состоянии, а не в рендере (`combat.freeze`), потому что меняет игру:
на эти кадры не идут телеграфы, и бой на медленной машине не должен отличаться
от боя на быстрой. Длина заморозки зависит от интервала оружия: клинки бьют
2.5 раза в секунду, и полная пауза на каждом попадании превратила бы бой в мигание,
а молот ощущался бы точно так же, как они.

**Отдача.** Попадание толкает бьющего назад — в воздухе сильнее, чем на земле,
иначе прыжок над боссом превращается в бесплатную позицию. Босса от удара ведёт
назад визуально (`boss.recoil`), прислужников отбрасывает по-настоящему.

**Удар вниз с отскоком.** Главное заимствование из Hollow Knight и единственная
новая механика в бою. Удар вниз в воздухе, попавший по боссу, прислужнику или
снаряду, подбрасывает игрока вверх и возвращает рывок. Летящие камни и перья от
такого удара разбиваются, столбы огня — нет.

Сбивать снаряды боковым ударом нельзя специально: иначе зажатая кнопка выметала
бы веер перьев Гарпии, и уклонение перестало бы быть нужным. Ударом вниз — можно,
и это единственный способ остаться в воздухе надолго. Риск и точность за это платят.

**Пропущенный удар** весомее любого своего: заморозка длиннее, тряска полная,
игрока отбрасывает от источника, по краям экрана пульсирует красная рамка на всё
время неуязвимости.

**Искры и пыль.** Симуляция расставляет отметки попаданий (`combat.impacts`:
где, куда и насколько тяжело), а рендер превращает их в разлетающиеся искры и
кольцо в точке контакта. Сами частицы живут в рендере и используют `Math.random`:
держать сотню частиц в сохранении и гонять их через ГПСЧ симуляции — это платить
детерминизмом за пыль под ногами. Тот же язык теперь и в шахте: удар киркой
выбивает крошку цвета породы, точный скол в слабое место — вдвое больше.

Проверяется всё это `npm run feel-check`: что попадание вообще замораживает кадр
и оставляет отметку, что на заморозке босс стоит, а искры гаснут, что удар вниз
отскакивает, а боковой не сбивает снаряды, что отбрасывание не выносит за стену
и что заморозка занимает разумную долю боя (сейчас 9.8% кадров — при 15% бой
начинает ощущаться рваным).

## Балансировка ботами

`npm run balance` прогоняет «каждое оружие против каждого босса» и печатает винрейты.
Бот изображает не идеального игрока, а компетентного: ищет ближайшую безопасную точку,
прыгает через низкие атаки, тратит рывок, когда уйти пешком уже поздно, и бьёт всегда,
когда достаёт.

Таблица строится по уровню дерева: `--tier 2` (по умолчанию) — сплавы, до которых
доходит обычный забег с рюкзаком на 20; `--tier 3` — то, ради чего спускаются дважды.
Ответ на босса проверяется не по названию материала, а по свойству: Голема вскрывает
пробой брони, щит Бездны — магический урон, чип-урон Гарпии окупает вампиризм.

Текущая картина (30 боёв на комбинацию, второй уровень дерева, без вставки):

| Босс | Лучшее | Узел-ответ работает? |
|---|---|---|
| Каменный Голем | Молот · Живой кристалл — 83% | да: литой обсидиан 80% и вдвое быстрее (39 с против 55 с), чистая сталь — 17% |
| Пепельная Гарпия | Клинки · Живой кристалл — 70% | да: сердечное железо 60%, любой молот — 0–10% |
| Повелитель Бездны | Молот · Гранёная призма — 47% | да: все пять узлов с магией сверху, всё остальное — 0–3% |

На третьем уровне ответы выражены ещё резче: осадный сплав против Голема, скорая
кровь и душевное стекло против Гарпии, звёздное ядро и душевное стекло против Бездны.
Первый босс при этом проходится любым узлом третьего уровня с винрейтом 87–100% —
балансировщик отмечает это отдельной строкой «уровень перерос босса», а не поломкой
баланса: 16 единиц сырья на оружие и должны окупаться.

### Что балансировщик нашёл и что было исправлено

1. **Магический урон проходил сквозь броню.** Кристалл игнорировал броню Голема
   наравне с обсидианом и был строго лучше него. По §3 это ответы на *разные* защиты:
   броню пробивает только обсидиан, щит проходит только магия. Формула в
   `sim/combat/damage.ts` переписана.
2. **Луч Повелителя был неуклоняемым.** Он перекрывал всю арену на 0.6 с, а рывок
   даёт лишь 0.15 с неуязвимости — гарантированные 25 урона каждый раз. Теперь луч
   бьёт от босса в сторону игрока до края арены: безопасное место — за спиной
   Повелителя, и добежать туда за 0.85 с телеграфа можно ровно с рывком.
3. **Вихрь Гарпии возникал мгновенно.** Зона 300×210 появлялась в момент удара,
   уйти из неё было физически нельзя. Теперь зона видна весь замах.
4. **Пикирование Гарпии довыцеливалось в момент старта** — телеграф в 0.55 с не
   предупреждал ни о чём. Теперь Гарпия занимает линию пола ещё на замахе, и
   пикирование перепрыгивается. Заодно хитбокс перестал висеть у стены после того,
   как Гарпия долетела до края.
5. **Ритм Гарпии не оставлял окон на контратаку.** С исходными паузами бот проводил
   в атаке 27% времени, и вампиризм кровавого железа не успевал окупаться — босс был
   непроходим любым оружием. Паузы после атак увеличены (0.4/0.35/0.4 → 0.6/0.45/0.5),
   телеграфы оставлены короткими: «быстрая, короткие окна» — это про длину телеграфа,
   а не про полное отсутствие пауз.

### Незакрытые находки

**Вампиризм выигрывает у пробоя брони по винрейту.** На Големе живой кристалл даёт
83% против 80% у литого обсидиана — бот выживает за счёт лечения. По времени боя
картина обратная: обсидиан убивает за 39 с, живой кристалл за 55 с. Считать это
поломкой рано: «медленно, но безопасно» — законная вторая стратегия, и она дороже
по здоровью. Проверять на плейтесте.

**Винрейт финального босса на втором уровне дерева (47%) — самый низкий из трёх.**
Так и задумано: Бездна — тот босс, ради которого спускаются за третьим уровнем.
Но цифру стоит держать в поле зрения.

## Проверка в браузере

Все три фазы и все экраны прогонялись в Chromium через Playwright: игра стартует без
ошибок в консоли, шахта генерируется и проходится, ловушки снимают здоровье, ковка
считает характеристики, бой доходит до второй фазы Повелителя со щитом. После перехода
на дерево крафта тем же способом проверены обе вкладки кузницы: соединение двух руд
в слиток, открытие нового узла, выбор основы на наковальне, мини-игра и выход на арену
с оружием из выкованного узла. Проверка разовая, в репозиторий не коммитилась.
