# Кузнец Судеб — памятка для работы над проектом

Роглайт про кузнеца: **добыча → ковка → бой с боссом**, 10–15 минут на забег.
Главная механика — игрок знает, какой босс его ждёт, **до** спуска в шахту,
поэтому сбор ресурсов это планирование, а бой — проверка плана.

Полное описание — в `README.md`, дизайн-документ — в `docs/design.md`,
план развития — в `docs/roadmap.md`.

## Правила, которые нельзя нарушать

Они не стилистические: на каждом стоит работающая проверка, и каждое было
куплено болью на плейтесте.

1. **Симуляция ничего не знает о рендере, вводе и звуке.** В `src/sim/` и
   `src/core/` нет ни одного импорта из `pixi.js`, DOM или `src/render/`.
   Благодаря этому балансировщик гоняет бои в Node без браузера.
2. **Состояние — простые данные.** Никаких классов с методами, `Map`, `Set`,
   функций внутри `GameState`: всё должно переживать `JSON.stringify` и
   восстанавливаться один в один, включая состояние ГПСЧ.
3. **Детерминизм.** Один сид → один результат. Симуляция не трогает
   `Math.random`, `Date.now` и частоту кадров. Косметика (искры, пыль,
   параллакс, звук) живёт в рендере, использует своё время кадра и свой
   источник случайности — ей это можно, состоянию нельзя.
4. **Мутации только через команды.** UI не меняет состояние напрямую: даже
   навигация по меню идёт через `MENU_MOVE` / `MENU_CONFIRM`. Сенсорный ввод
   превращается в те же команды, что и клавиши.
5. **Фиксированный шаг 60 Гц** с накопителем, интерполяция при отрисовке.
   Каждая сущность хранит `px`/`py` — позицию на прошлом тике.
6. **Ни одного магического числа в коде симуляции.** Всё, что влияет на
   ощущение игры, живёт в `src/core/constants.ts`.
7. **Наблюдатели состояния вместо событий.** Симуляция не рассылает события:
   рендер и звук сравнивают текущий кадр с предыдущим (новые `impacts`,
   выросший `craftCount`, добавившийся результат ковки). Если нужно новое
   событие — добавляй в состояние **монотонный счётчик или растущий id**,
   а не затухающий флаг: по флагу два одинаковых события подряд неотличимы.

## Раскладка

```
src/
  core/      чистые данные: типы, константы баланса, ГПСЧ, команды, дерево предметов
  sim/       симуляция. НИ ОДНОГО импорта из PixiJS или DOM
    mine/    генерация шахты и её шаг
    forge/   верстак (дерево крафта), наковальня, вывод характеристик оружия
    combat/  игрок, боссы, опасности, расчёт урона
    game.ts  корень: dispatch(команда) и tick()
  render/    PixiJS. Только читает состояние и рисует
  audio/     синтез звука и наблюдатель состояния
  input/     клавиатура и сенсорный экран → команды
  persist/   сохранение между фазами
tools/       бот, балансировщик и проверки (headless, без браузера)
```

## Проверки

Гоняй перед коммитом; все шесть стоят в CI на каждый пуш в `main`.

```bash
npm run typecheck
npm run determinism      # один сид → один результат
npm run mine-check       # до каждой жилы и до подъёмника можно допрыгнуть
npm run deadlock-check   # из любого положения есть выход
npm run input-check      # тап берёт ступеньку, зажатая кнопка бьёт повторно
npm run feel-check       # заморозка кадра, отскок, отбрасывание, буферы нажатий
npm run audio-check      # события состояния → нужные звуки, без браузера
npm run balance          # винрейты; --tier 3, --boss abyss, --inlay basalt
```

**Каждая проверка появилась после конкретной поломки.** Если чинишь баг,
которого не ловит ни одна из них, — добавь проверку туда же, а не только фикс.

## Стиль

- **Комментарии и коммиты по-русски**, как и весь проект.
- Комментарий объясняет **почему**, а не что: «зона окна шире перезарядки
  кирки, иначе попасть в ритм нельзя», а не «увеличиваем зону».
- Числа баланса — с обоснованием рядом, в `constants.ts`.
- Не добавляй зависимостей без нужды: в игре нет ни одного ассета и почти нет
  библиотек, и это осознанный размен ради веса сборки под Яндекс Игры.

## Как это запускать и смотреть

```bash
npm run dev      # разработка
npm run build    # проверка типов + сборка в dist/
npm run preview  # посмотреть собранное
```

Игру можно и нужно смотреть глазами: Chromium с Playwright уже стоит
(`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`, `playwright install` запускать не
надо). Быстрый способ попасть в нужную фазу без прохождения — собрать состояние
скриптом на `tsx` и положить его в `localStorage` под ключом
`kuznec_sudeb_save_v1` через `page.addInitScript`.

## Публикация

`main` → GitHub Actions → GitHub Pages: https://fleuki.github.io/Kuzneca_sudeb/
Сборка из веток не публикуется. Если workflow упал на шаге «Set up job» с
`429 Too Many Requests` — это сбой на стороне GitHub, помогает перезапуск.

Пуш идёт в ветку `claude/...`, дальше — pull request. **В `main` напрямую не
пушить.**

## Что уже решено и не обсуждается заново

- Крафт — дерево предметов, где **два предмета дают один**. Не «12 + 6».
- Врагов в шахте нет: опасность создают только ловушки.
- Блока и парирования нет, уклонение — единственная защита.
- Арена — один экран без прокрутки.
- Звук синтезируется, ассетов нет (кроме тех, что придут от художника).
